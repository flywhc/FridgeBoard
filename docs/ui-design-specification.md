# FridgeBoard UI 设计规范

状态：项目级强制规范  
版本：1.1
更新日期：2026-08-06

## 1. 目的与适用范围

本规范统一 FridgeBoard 手机 PWA 与冰箱端显示设备的跨页面布局、视觉语言和交互基线，解决不同设计稿或实现阶段出现的品牌、标题、间距和操作区漂移。

它不替代具体场景的最终设计稿和功能规则，而是约束所有页面共享的部分。新增页面、修改既有页面、从设计稿生成代码以及视觉验收时均必须遵守。

## 2. 依据与冲突处理

按以下顺序判断实现依据：

1. `docs/functional-design-and-feasibility.md` 决定功能、信息与交互语义。
2. 本规范决定跨页面布局、样式、组件和响应式基线。
3. `docs/final-ui-designs.md` 登记的最终设计稿决定具体页面的内容编排与场景细节。
4. 现有代码只能作为实现参考，不能反向覆盖前三项。

最终设计稿与本规范的共享规则不一致时，以本规范为准；不得选择性照搬不一致的标题位置、边距或控件样式。若差异会明显改变页面信息层级或核心交互，先记录“规范—设计稿冲突”并请产品确认，不得自行折中。

## 3. 品牌与命名

- 产品中文名统一为“家常食橱”，不得写成“家常食厨”或其他变体。
- 品牌字标只表达产品身份，不替代当前页面标题。
- 同一屏幕只设置一个一级页面标题。品牌字标、冰箱名称、步骤名不得同时使用一级标题样式。
- 用户创建的冰箱名称属于上下文信息；需要切换冰箱时放在顶部栏右侧入口或标题下方，不得挤占品牌字标的视觉中心。

## 4. 基础设计令牌

### 4.1 颜色

| 语义 | 色值 | 用法 |
| --- | --- | --- |
| 纸张背景 | `#F2F2EE` | 页面默认背景 |
| 内容背景 | `#FFFFFF` | 卡片、输入框、二维码底色 |
| 主文字/主边框 | `#111111` | 标题、正文、主要按钮、轮廓 |
| 次级文字 | `#777777` | 辅助说明、时间、弱化信息 |
| 分隔线 | `#D7D7D2` | 列表分隔和非选中边框 |
| 警告强调（仅手机端） | `#B6402B` | 错误或危险操作的渐进增强 |
| 正常强调（仅手机端） | `#4F6653` | 成功或新鲜状态的渐进增强 |

状态含义必须在黑白或一位色显示下仍可识别。颜色不能作为唯一信息载体；必须同时使用文字、图形、边框粗细或纹理。

### 4.2 字体

- 字体栈统一为 `Arial, "Helvetica Neue", sans-serif`，数字与日期使用等宽数字特性。
- 手机端品牌字标：12–13px、700、字距 `0.16em`。
- 手机端内容页一级标题：28px、700；顶部导航栏标题：16–18px、700。
- 手机端分组标题：18px、700；正文和表单控件不得小于 16px；辅助文字不得小于 12px。
- 冰箱端页面标题：30–36px、700；关键数量：24–32px、700；标签：18–22px；辅助信息：16–18px。
- 标题允许紧凑字距，但不得通过绝对定位或负边距制造视觉居中。

### 4.3 间距、边框与圆角

- 以 8px 为基础间距单位；常用间距只使用 4、8、12、16、24、32、40、48px。
- 手机端水平安全边距为 16px；冰箱端为 20–24px。
- 手机端交互热区最小 48×48px；冰箱端最小 56×56px。
- 默认边框 2px；选中或警告 3px；过期或破坏性强调 4px。
- 冰箱端圆角 0–4px；手机端控件圆角 8–12px。
- 不使用阴影、玻璃效果、模糊背景、渐变或仅装饰性的纹理。斜纹仅用于确定性的状态表达。

## 5. 页面骨架

页面只允许由以下区域按顺序组成：

```text
系统安全区
顶部栏（品牌栏或页面导航栏）
页面标题/上下文（仅在该页面类型需要时）
可滚动主内容区
固定或随内容排列的主要操作区
底部安全区
```

- 顶部栏必须位于页面顶部并参与正常文档流；允许 `sticky`，不得用任意 `top` 值或垂直居中容器定位。
- 普通页面不得用 `justify-content: center` 垂直居中整个页面。只有首次开机、配对成功、空结果等明确的单任务状态页可以垂直居中主体；其顶部品牌仍保持在顶端。
- 页面根容器至少占满 `100dvh`，并处理 `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)`。
- 长内容只滚动主内容区。顶部栏和固定操作区不得覆盖标题、表单末项或反馈信息。
- 手机端顶部栏与底部导航/操作区共同构成固定的应用壳；它们之间的主内容区独立滚动，标题栏不得随主内容滚动。
- 手机 PWA 必须使用 `viewport-fit=cover` 并关闭用户缩放；根页面禁止滚动，只有应用壳内明确标记的主内容区允许纵向滚动。
- 系统顶部安全区（时间、信号等）必须与顶部栏使用同一应用壳背景色；不能因 `body` 或 PWA `theme-color` 仍使用页面纸张背景而出现色差。

## 6. 顶部栏与标题

### 6.1 手机端一级页面

适用于当前冰箱、食谱、补货、我的冰箱等主入口：

- 顶部使用共享标题栏；无具体页面标题时显示品牌字标“家常食橱”，有明确一级页面标题时显示该标题。标题始终在**视口水平中心**，不以剩余空间为中心。
- 顶部栏采用三列网格：`48px minmax(0, 1fr) 48px`。左、右入口即使缺失也保留等宽占位。
- 左侧放全局导航入口；右侧放冰箱切换、设置或该页唯一的高频操作。
- 页面不应再在内容区重复显示同一一级标题，不得把标题推到右侧或通过内容区布局伪造居中。

### 6.2 手机端二级页面与流程页

适用于编辑食材、布局编辑、提醒设置、单日食谱编辑等：

- 顶部使用页面导航栏：左侧返回，中间当前页面标题，右侧放至多一个文字或图标操作。
- 导航栏同样采用 `48px minmax(0, 1fr) 48px` 三列网格。标题在视口水平中心，左右内容不等宽时也不得偏移。
- 返回、标题和右侧操作垂直居中；标题单行截断，不换行挤高顶部栏。
- 不在导航栏中再次显示大号品牌字标。需要品牌识别时使用应用壳或启动页，不与页面标题争夺层级。

### 6.2.1 手机端通用顶部标题栏约束

所有手机页面都必须有同一风格的顶部标题栏，顶部栏采用“左侧按钮｜居中标题｜右侧按钮”的三列结构：

- 左侧按钮、右侧按钮均为可选；缺少按钮时仍保留对应的 `48px` 等宽占位，确保标题以视口中心对齐，不受另一侧内容宽度影响。
- 标题栏下边界必须有一条分割线，视觉语义与底部导航栏上边界一致；分割线使用分隔线令牌，不使用页面内容边框替代。
- 标题栏背景色必须与底部导航栏/底部固定操作区相同，并与中间页面背景区分开。默认使用 `内容背景 #FFFFFF` 作为应用壳背景，页面主内容使用 `纸张背景 #F2F2EE`。
- 顶部标题栏必须固定在屏幕应用壳内，不参与主内容滚动；长内容只能在标题栏与底部固定区之间的区域滚动。
- 没有底部导航栏的页面仍必须保留顶部标题栏；这类二级页面左上角必须是返回按钮，不得以浏览器返回或正文文字链接替代。
- 标题栏、标题和两侧控件复用共享实现；页面只能传入标题、返回行为和右侧操作，不得单独覆盖三列宽度、字号、对齐和分割线。

### 6.3 冰箱端页面

- 首页顶部固定展示当前页面标题、库存/同步上下文和刷新入口；不得把标题放进冰箱图形内部。
- 分区详情、补货清单和配对页使用三列顶部栏：返回、居中标题/区域缩略图、刷新或状态入口。
- 冰箱端顶部栏热区不小于 56px；禁止悬停、滑动和长按依赖。
- 页面标题和操作在滚动时保持可见；无滚动页面也必须占据顶部固定区域。

### 6.4 允许的例外

- 相机/扫码页可以使用深色沉浸式顶部栏，但品牌或页面标题仍位于顶部，不得漂浮在取景框中。
- 首次开机、配对成功、加载完成等状态页可垂直居中主体插图和结果文案；品牌栏仍固定在顶部安全区之后。
- 需要持续交互、滚动、预览或多个步骤的复杂流程使用全屏流程页，复用 `PageShell` 与 `PageHeader`；不得把这类流程伪装成居中模态框。全屏流程页必须有明确标题和左上返回入口。

## 7. 内容、表单与操作区

- 手机端主内容以单列为默认；相邻区块垂直间距 24px，区块内元素间距 8–16px。
- 卡片只用于确有分组语义的内容，不把每段文字都装入卡片。列表优先使用分隔线保持信息密度。
- 表单标签置于控件上方，必填与可选状态明确；输入、选择和按钮高度至少 48px。
- 每屏只能有一个主操作。次操作使用描边或文字样式，危险操作不得与主操作同色同权重。
- 固定底部操作区必须包含底部安全区内边距，并为主内容预留等高空间。
- 加载、空数据、错误、禁用、离线、长文本和最窄 320px 宽度都必须有明确布局，不得依赖内容恰好较短。

## 8. 图标与状态

- 图标使用 24×24 或 32×32 网格、2–3px 描边，并保持同一端内的线宽一致。
- 图标按钮必须提供可访问名称；图标本身不等于点击热区。
- 新鲜为普通轮廓；临期为双边框与斜纹角标；过期为黑底感叹号。未填写 BBD 不显示异常状态。
- 同一状态在冰箱端与手机端使用同一符号语义，不得逐页发明新徽记。

### 8.1 面向用户的位置名称

- 任何面向用户的存放位置文字必须由区域显示名和可读序号组成，例如“冷藏室 · 第 1 格”；禁止渲染数据库 ID、布局 key 或内部编码，例如 `refrigerator-1`、`slot-001`。
- 位置名称在新增、编辑、列表、通知和确认弹窗中统一复用同一格式化函数；不得由页面自行拼接 `zone.label + slot.key`。

### 8.2 通知与错误反馈

- 会阻断当前操作、需要用户知晓的错误使用共享居中通知弹窗：半透明遮罩、白色内容面、右上角关闭按钮、标题、具体说明与单一“知道了”操作；不得在页面内容区临时插入孤立错误段落。
- 字段级校验可在对应控件附近说明；跨字段校验、网络失败、权限失败和保存失败使用通知弹窗。通知文案必须说明用户可采取的下一步。
- 共享通知弹窗须复用统一组件和令牌，支持标题、正文、关闭回调及可访问的 `dialog` 语义。

### 8.2.1 手机端统一居中模态框

手机端居中模态框只用于短时阻断、确认、通知或小型选择，不承载完整页面导航。它与一级页面、带左上返回按钮的二级页面、底部抽屉是不同的交互类型。

- 模态框由共享 `Dialog` 实现；页面不得自行复制遮罩、卡片、关闭按钮或操作区 CSS。
- 外层遮罩固定覆盖应用视口，使用 `rgb(17 17 17 / 45%)`；遮罩只用于阻断底层交互和建立层级，不得改为不透明页面背景，也不得使用阴影、模糊或玻璃效果。
- 内容面使用 `#FFFFFF`，宽度为 `min(100%, 358px)`，左右安全边距 `16px`，上下安全区使用 `env(safe-area-inset-top/bottom)`；边框 `2px solid #111111`，手机端圆角 `10–12px`。
- 内容面最大高度不得超过可用视口；长正文或列表只在内容面内部滚动，不能让底层页面或整个应用壳滚动。
- 标题、正文和操作区按文档流排列。关闭按钮若存在，必须位于共享弹窗头部的独立 `48×48px` 热区内，不得用绝对定位覆盖标题或正文。
- 通知弹窗使用“关闭按钮 + 标题 + 正文 + 单一‘知道了’”结构；确认弹窗使用“标题 + 说明 + 主操作 + 取消”结构，已有“取消”时不重复增加右上角关闭按钮。
- 主操作使用黑底白字，取消/次操作使用白底黑字描边；操作区垂直排列，按钮高度至少 `52px`，间距 `8–12px`，不得继承页面固定底部操作区的外边距。
- 模态框必须使用 `role="dialog"` 和 `aria-modal="true"`，标题通过唯一 ID 与 `aria-labelledby` 关联；加载中的无操作状态可使用共享 `Dialog` 的 `role="status"` 变体。
- 点击遮罩、按 `Escape` 是否关闭由业务语义明确决定；破坏性或不可逆确认不得因误触遮罩而关闭，必须提供明确的取消操作。
- 底部抽屉单独遵循抽屉规范，不套用本节的居中卡片结构；Kindle 页面因旧 WebKit 技术限制不纳入手机端 `Dialog` 组件迁移。

### 8.3 顶部栏弹出菜单

所有手机端顶部栏右侧的扩展操作、筛选、历史和导入菜单，统一以“每周食谱”页面右上角菜单为视觉基线；不得按页面重新设计一套下拉框。

- 触发按钮使用无边框、透明背景的 `48×48px` 图标按钮，图标使用 `24×24px` 线框 SVG，按钮必须提供明确的 `aria-label`、`aria-haspopup="menu"` 和 `aria-expanded`。
- 菜单相对右侧触发按钮定位，顶部紧贴按钮下方（`top: 48px`），右边缘与按钮右边缘对齐；宽度统一为 `176px`。
- 菜单使用内容背景 `#FFFFFF`、主边框 `#111111` 的 `2px` 边框和 `10px` 圆角；不得添加阴影、投影、标题栏、额外说明区或黑色浮层背景。
- 菜单项统一为至少 `48px` 高的两列网格：左侧 `24px` SVG 图标，间距 `12px`，右侧文字；水平内边距 `12px`、垂直内边距 `10px`，文字使用正文级 `16px`。
- 菜单项之间使用 `1px` 分隔线，最后一项不显示底部分隔线；图标统一为 `24×24px`、`2px` 描边、当前文字色。
- 菜单项支持键盘/触摸焦点，焦点使用主色 `3px` 外框；菜单语义使用 `role="menu"` 与 `role="menuitem"`，可选项菜单可补充 `role="menuitemradio"` 和 `aria-checked`，但不得自行增加黑底选中态。
- 可选项菜单必须在当前选项文字右侧保留固定宽度的对勾位置；当前项显示 `24px` 以内的线框对勾，其他项保留空位以避免文字横向跳动。当前排序方案等用户偏好应持久化到本地，下次打开同语义页面时沿用并继续显示对勾。
- 点击触发按钮再次关闭菜单；点击菜单外区域、选择菜单项或按 `Escape` 关闭菜单。菜单不得遮挡顶部标题，320px 宽度下不得横向溢出。
- 新增页面若需要同语义弹出菜单，必须复用该结构、令牌和共享实现；如果设计稿提出不同的宽度、圆角、阴影或选中态，先记录“规范—设计稿冲突”并确认后才能实现。

### 8.4 物品多选与移动

- 物品列表行的分类图标保留原有 `48×48px` 尺寸和位置，选择按钮不得改变整行高度或挤压左侧名称、分类、添加天数、有效期和备注。
- 未选中图标使用普通图标状态；选中后图标使用灰度/降低不透明度，并在同一图标热区中央叠加 `24×24px` 左右的线框对勾。选择按钮必须有 `aria-pressed` 和可访问名称。
- 选中态底部操作区沿用统一底部操作栏和安全区；“取消”为描边次操作，“移动”为黑底主操作。至少有一项选择时隐藏“添加物品”。
- 目标冰箱列表使用统一弹出菜单的黑白、边框、圆角、分隔线语言；确认位置页面复用二级页面顶部栏、冰箱预览、位置标签和底部主操作区，不另造一套布局。
- 多选确认摘要只保留第一项分类图标，文字从第一项物品名称开始，后续物品名称用逗号连接；摘要单行省略，不显示最终数量。

## 9. 响应式基线

- 手机端设计基准为 390×844px，同时验证 320、390、430px 宽度；页面宽度流式适配，不锁死 390px。
- 手机端宽屏时内容容器居中，但顶部栏的视觉中心仍以容器中心为准。
- 冰箱端按约 3:4 竖屏比例设计，至少验证 540×720px；不得写死 Kindle 型号或单一分辨率。
- 禁止使用依赖固定内容高度的巨大 `margin-top`、负边距或绝对定位来摆放标题和主要操作。

### 9.1 冰箱预览完整显示契约

- 所有手机端冰箱图必须通过共享 `FridgePreviewFrame` 展示；页面只能声明可用矩形和展示上限，不得再覆盖 `OpenFridge` 的宽度、高度、`aspect-ratio` 或内部列结构。
- 预览必须按同一缩放比例适配最长边，计算关系为：`scale = min(availableWidth / shellWidth, availableHeight / shellHeight, maxWidth / shellWidth)`；最终宽高都由该比例产生。
- 禁止使用“先按宽度放大，再用 `max-height`、`overflow: hidden` 或固定高度截短”的组合。窄高容器必须先按高度反推宽度，冰箱外壳和下部内容必须完整可见。
- 修改共享预览尺寸时，必须同时更新 `fridgeGeometry` 的尺寸回归测试、首页 320/390/430px 视口检查，以及宽矮和窄高容器检查；不能只验证一个标准手机截图。
- 代码审查重点：搜索 `.open-fridge` 的页面级尺寸选择器，确认没有遗留的 `width`、`height`、`aspect-ratio`、`grid-template-columns` 或 `max-height` 规则重新接管共享组件。

## 10. 共享组件与实现约束

- 顶部栏、页面壳、底部操作区、按钮、表单控件、状态徽记和卡片必须复用共享实现，不得在各页面复制一套略有差异的 CSS。
- 页面级组件只配置标题、返回行为、右侧操作和是否固定；不得自行覆盖共享顶部栏的网格列宽、字号和对齐方式。
- 颜色、字体、间距、圆角、边框和热区尺寸应定义为设计令牌；业务组件不得散落魔法数。
- 新增例外前先确认能否归入第 6.4 节；确需新增时，必须同步更新本规范和共享组件测试。

建议共享接口至少覆盖以下语义，不强制具体命名：

```text
PageShell(surface, header, footer, scrollMode)
AppHeader(leftAction, wordmark, rightAction)
PageHeader(backAction, title, rightAction)
BottomActionBar(primaryAction, secondaryAction)
```

### 10.1 DP75SDI Kindle 冰箱端实现约束

`DP75SDI` Kindle Paperwhite 的实验性浏览器是本项目 Kindle 端的已验证最低能力基线。
所有 Kindle 页面必须使用独立的 ES5 页面壳和 `XMLHttpRequest` 数据层，不得复用手机
PWA 的 React/ES Module 运行时；完整能力矩阵与 API 约束见
[功能设计 §12.4](functional-design-and-feasibility.md#124-已验证-kindle-paperwhite-兼容性基线dp75sdi)。

- 页面在 JavaScript 执行前必须呈现标题、当前状态或错误说明；禁止把唯一可见内容放在
  React 挂载点或异步成功回调中。
- 禁止把 CSS Grid、Flexbox、现代 URL API、`fetch`、Promise 或动态导入作为必要布局/交互
  条件；尚未实测的能力只能作为渐进增强。
- DP75SDI 实机 Spike 进一步确认：所有 Kindle 页面关键布局必须使用普通块级元素、table
  或 inline-block，不得依赖 Flex/Grid；关键中文字号优先使用传统 `<font size="4|5">`
  或同等兜底，CSS px 只作为增强。所有页面必须使用 ES5 + `XMLHttpRequest`，设置请求超时，
  显示错误/离线/过期/撤销状态；每个页面完成后都必须在 DP75SDI 上完成
  主流程和 3:4 竖屏截图验收。完整结果见 [Kindle DP75SDI 能力 Spike](kindle-capability-spike.md)。
- 所有 Kindle 页面外层内容区及顶部操作行，左右必须至少保留 `20px` 实机可见留白；
  优先使用已在 DP75SDI 验证有效的父元素 inline `padding-left/right`、子元素 inline
  `margin-left/right` 或 table 空白单元格，不得只依赖现代 CSS shorthand 或未实测布局能力。
- Kindle 刷新图标必须使用与手机端一致的 `24×24` SVG viewBox、`overflow: visible`、
  `vertical-align: middle` 和圆角描边；所有页面共用同一垂直对齐，不得为单个刷新按钮添加位移。
- Kindle 页面壳不得照抄其他 Kindle 型号的固定像素宽度。外层 `html`、`body`、页面和内容区
  必须使用 `width: 100%`；关键正方形区域（二维码、布局图、分区图）须在 ES5 初始化阶段基于
  `document.documentElement.clientWidth/clientHeight` 计算像素尺寸，并同时受可用高度约束。禁止
  以固定宽高、`vw`/`vh`、`calc()` 或 CSS `aspect-ratio` 作为关键尺寸前提。
- 老 WebKit 的满屏垂直页可使用已实测的 `-webkit-box`/`-webkit-flex` 作为渐进实现，但页面仍须在
  其不可用时保持常规块级流式布局可读；不得因 `overflow: hidden` 裁掉标题、状态或主要操作。
- 冰箱端共享页面壳、顶部栏、按钮和错误状态应在 ES5 资源中复用，不能复制手机端组件。
- 视觉验收除 540×720px 桌面模拟外，必须包含 DP75SDI 的真实截图；实机不通过时不得以
  现代浏览器截图替代。

## 11. 视觉核验与交付门槛

每个 UI 任务交付前必须完成：

1. 记录对应场景、最终草稿 ID 和预览 URL。
2. 对照本规范检查页面类型、顶部栏、标题层级、边距、控件和状态语义。
3. 手机端至少截图核验 390×844px，并检查 320px 与 430px 宽度；冰箱端至少截图核验一个 3:4 竖屏视口。
4. 居中标题的几何中心与内容容器中心误差不得超过 2px；不能只凭肉眼判断“看起来差不多”。
5. 检查长标题、系统字体放大、加载、空、错误、离线和禁用状态。
6. 在交付说明中列出已核验视口、结果和仍存在的设计稿冲突。

出现以下任一情况不得声明 UI 完成：

- 品牌字标或页面标题不在规定的顶部区域。
- 应居中的标题受左右按钮宽度影响而偏移。
- 通过固定高度、巨大外边距或绝对坐标把标题“摆到”目标位置。
- 页面之间同语义控件的字号、边框、圆角或热区不同。
- 无法访问设计稿且没有用户提供的截图或结构说明。

# 测试策略

## 测试分层

- 发布 smoke：`npm run test:smoke`，只回答“当前提交能否启动并完成最关键业务链路”。后端覆盖启动、健康检查、移动认证、设备配对、库存 CRUD 和食谱完成/撤销；前端覆盖 API/SSE、移动会话、PWA 缓存、日期边界和权限。
- 相关回归：实现或修复时运行直接受影响的测试文件或节点，并按代码类型补 lint、类型检查或构建。新增行为应优先测试公开输入输出和用户可观察结果。
- 全量回归：由 GitHub Actions 在 pull request 和 `main` 推送时运行。高风险改动或目标提交没有成功 CI 记录时，在发布前本地补跑受影响范围的全量门禁。

## 测试取舍

保留以下测试：业务不变量、状态转换、数据持久化、API schema/status、安全与权限、错误脱敏、并发/竞态、缓存一致性、跨平台协议，以及曾发生且可复现的缺陷。

不新增或应删除以下测试：

- “今天”改成“周一”一类普通展示文案的精确匹配；
- CSS 像素值、类名或源码片段的存在性检查，但没有渲染结果或行为验证；
- 私有函数调用顺序、组件内部接线和其他重构即失败的实现细节；
- 与已有测试验证同一风险、且不增加边界或失败路径的重复用例。

法律/安全提示、协议常量、无障碍名称和用户必须据此采取行动的错误信息本身属于产品契约，可以精确断言。视觉回归应使用设计稿对照或针对性的渲染验收，不用源码字符串测试代替。

## 发布边界

正常发布不重复执行已由 CI 证明通过的全量测试、lint 和本地 Docker 构建。`scripts/deploy-image.sh` 仍负责从指定提交构建生产镜像、备份数据库、等待容器健康并检查公网 `/healthz`；移动端工作流仍负责签名构建与产物校验。

以下情况必须扩大验证：数据库迁移；认证、授权、安全或日志；外部 API/存储契约；依赖、Docker、CI、发布脚本或移动构建链变更；跨模块重构；CI 失败或没有目标提交的成功记录。

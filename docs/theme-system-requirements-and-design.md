# PWA 与手机端主题系统：需求分析及技术设计提案

状态：视觉方向已确认，主题基础设施已实现，拟物 Soft-3D 母版切片与通用布局算法已覆盖七种模板，拟物分类图标 46/46 已接入 Thiings 3D 资产，卡通皮肤待实现
版本：0.3
日期：2026-08-18

## 1. 目标与结论

在不改变冰箱、库存、食谱和分类业务语义的前提下，为 PWA 与 Capacitor 手机端增加三套可切换主题：

- `ink`：水墨屏主题，保持当前黑白视觉和既有冻结设计稿。
- `skeuomorphic`：拟物主题，以真实冰箱材质、层次和有节制的立体控件为特征。
- `cartoon`：卡通主题，以明快配色、粗轮廓和简化形体为特征。

主题必须同时控制应用设计令牌、冰箱外观和分类图标，但不得改变布局几何、交互流程、状态语义或业务数据。首期把主题定义为当前 PWA/手机 App 安装实例的本机偏好，默认值为 `skeuomorphic`，不向不同设备同步。

冰箱渲染不把整张概念图当作可点击背景。现有 `fridgeLayoutCore` 继续提供唯一业务布局，拟物和卡通主题共用资产驱动的 2.5D 拼接器：柜体皮肤、白色/玻璃隔板、固定透视门体、门架、合页和主题图标按同一布局计划组合。柜体、内胆和边框可作为一个逻辑皮肤，前景边框按遮挡需要保留独立层；抽屉不作为首期必需元素。

首期不承诺任意门数或完全自由绘制冰箱。当前功能设计明确排除“完全自由绘制冰箱结构”，现有核心也只支持七种固定模板。主题资产和渲染接口应避免写死模板名，为将来扩展门数保留能力，但结构扩展必须作为独立需求评审。

## 2. 现状证据

### 2.1 客户端与设置入口

- PWA 与 Capacitor 手机端共用 `frontend/src/App.tsx` 和同一套 React/CSS；不需要维护两套主题实现。
- “我的”页已存在未接线的“应用偏好”入口，页面注释明确该页承载账号和本机偏好。
- 当前页面颜色、边框和圆角主要由 `frontend/src/styles.css` 的全局 CSS 变量控制，具备令牌化改造基础。
- PWA `manifest.webmanifest` 的 `background_color` 和 `theme_color` 固定为白色；运行时还需要同步 `<meta name="theme-color">`，避免系统安全区与主题顶部栏不一致。

### 2.2 冰箱布局

- `frontend/src/fridgeLayoutCore.js` 是手机 React 与 Kindle 共用的唯一布局计划来源，输出外壳尺寸、柜体分带、门分段和合页轨道。
- `frontend/src/FridgeLayout.tsx` 把渲染计划转换为柜体、门、分区、格位和合页 DOM。
- `frontend/src/fridgePreview.css` 统一控制 setup、editor、location、home 和 thumbnail 五种预览尺寸。
- 当前支持 `top_freezer_single`、`bottom_freezer_single`、`side_by_side`、`french_door`、`mini`、`three_door`、`dual_middle` 七种模板；现有实现并不支持任意门数。

### 2.3 分类图标

- 内置目录现有 46 个逻辑图标和 46 个小类，全部只有一个 SVG 文件。
- `FoodCategory.icon_key` 指向逻辑图标键；`IconAsset` 当前同时承担逻辑身份与单个文件存储。
- 自定义 AI 图标按冰箱保存为一个透明 PNG；分类只能绑定一个 `icon_key`。
- 图标 API 当前只返回单个 `asset_url`；前端各页面直接使用该 URL。
- 运行时图标已通过 Cache Storage 持久化，但缓存键还没有主题维度。

## 3. 范围

### 3.1 首期包含

1. “我的”页面接通“应用偏好”，增加“主题设置”二级页。
2. PWA 和 Capacitor 手机端即时切换并持久化三种主题。
3. 页面壳、顶部栏、底部导航、按钮、输入、弹窗、状态和冰箱预览使用主题令牌。
4. 七种现有冰箱模板在五种预览场景下使用主题化 2.5D 柜体、门、隔板、合页和图标皮肤。
5. 46 个内置分类图标各提供 `ink`、`skeuomorphic`、`cartoon` 三个变体。
6. 自定义图标可按主题分别生成或设置；缺失目标主题时使用已有变体兜底。
7. 图标接口、数据迁移、文件清理、访问控制和离线缓存支持主题变体。
8. 无障碍、窄屏、离线、加载失败和升级兼容验收。

### 3.2 首期不包含

- Kindle 或其他冰箱显示设备的主题切换；显示端继续使用现有水墨屏视觉。
- 用户自定义主题、跟随系统深色模式、定时切换主题。
- 完全自由绘制冰箱、任意门数或新增冰箱结构模板。
- 为每个商品自动生成三套图标。
- 主题跨设备或跨账号同步。
- 首期重做所有冻结页面的信息架构和交互流程。

## 4. 用户需求与验收规则

### 4.1 主题选择

- 默认主题为拟物；既有用户升级后已保存的视觉不能变化。
- 用户从“我的 → 应用偏好 → 主题设置”进入主题页。
- 主题页显示三个单选项，每项包含名称、简短风格说明、同一冰箱缩略图和分类图标示例。
- 点击选项立即预览并保存，无额外“保存”按钮；返回后保留选择。
- 页面刷新、PWA 重启和 App 重启后恢复上次选择。
- 本机没有已保存值、值损坏或来自未知版本时回退到 `skeuomorphic`。
- 切换主题不得清空页面数据、重置当前冰箱、改变滚动位置或触发业务 API 写入。

### 4.2 主题作用范围

- 主题作用于整个手机应用壳和业务页面，而不只作用于冰箱图片。
- 布局、文案、信息层级、热区尺寸和操作顺序在三主题间保持一致。
- 新鲜、临期、过期、离线、错误和选中状态不能只依赖颜色区分；继续使用文字、图形、边框或纹理表达。
- 主题切换不使用大幅动画；支持 `prefers-reduced-motion`，切换过程不得闪白或先显示错误主题。

### 4.3 内置分类图标

- 每个内置逻辑图标必须拥有三种主题变体；主题切换后所有页面使用同一逻辑图标的对应变体。
- 三个变体表达同一物品，不得因造型差异导致类别含义变化。
- 图标透明背景、居中、留白和视觉重量必须一致，在 20、28、32、48、56px 展示尺寸下可辨认。
- `ink` 优先使用现有 SVG；拟物和卡通可以使用透明 PNG/WebP，但 API 必须返回准确媒体类型。

### 4.4 自定义图标

- 自定义图标属于一个逻辑图标集，可拥有 1–3 个主题变体；分类仍只绑定逻辑 `icon_key`。
- 创建自定义小类时，默认在当前主题下生成或选择第一个变体。
- 用户可在自定义小类编辑页切换主题标签，为缺失主题生成、上传或替换变体。
- 页面必须明确区分“当前主题专用图标”和“正在借用其他主题图标”，但借用状态不应在日常库存页面显示提示。
- 目标主题存在变体时必须精确使用；不存在时按下列顺序选择：
  1. 该图标集保存的 `fallback_theme`；
  2. `ink`；
  3. `skeuomorphic`；
  4. `cartoon`。
- 第一个确认的自定义变体自动成为 `fallback_theme`。因此只设置一个主题时，其他主题始终使用这一个图标，符合用户要求。
- 替换某个主题变体不能改变分类 ID、逻辑图标键或其他主题变体。

## 5. 交互设计

### 5.1 “我的”页面

保留现有“应用偏好”列表行，将其接到二级页面。列表副文案改为当前值，例如“主题：拟物”；不在一级页直接放三个按钮，避免挤占账号与帮助信息。

### 5.2 应用偏好页

首期只有“主题”一项时仍使用标准二级页面壳，标题为“应用偏好”。主题列表行显示当前主题并进入“主题设置”。这样后续增加字号、触感或动效偏好时无需再次改导航结构。

### 5.3 主题设置页

- 使用三列顶部栏：返回、居中标题“主题设置”、右侧等宽空位。
- 主内容为三个纵向单选行，不使用嵌套卡片。
- 每行左侧为稳定尺寸的冰箱缩略图和三个示例分类图标，右侧为主题名、说明和单选状态。
- 选中后当前页面也立刻切换，用户可以直接比较页面壳与预览效果。
- 320px 宽度下预览和文字改为上下排列，选项热区仍不小于 48px。
- 加载某主题资产失败时保留主题选择，并对失败资产使用水墨屏或自定义图标兜底；阻断性失败使用共享通知弹窗。

### 5.4 自定义图标编辑

- 延续现有“从图库选择 / Agnes AI 生成”分段控件，在其上方增加“水墨屏 / 拟物 / 卡通”主题分段控件。
- 当前主题已有变体时显示缩略图和“替换”；缺失时显示实际兜底图标并标注“当前借用：水墨屏”等来源。
- 确认新变体前展示最终 48px 与 28px 两种尺寸，避免只在大图下看起来合格。
- 若从内置图库选择逻辑图标，直接复用其完整三主题图标集，不复制文件。

## 6. 视觉系统

### 6.1 共享语义令牌

新增主题注册表，页面只能使用语义令牌，不直接判断主题名。至少包含：

```text
surface.app / surface.shell / surface.content / surface.control
text.primary / text.secondary / text.inverse
border.default / border.strong / focus.ring
status.danger / status.warning / status.success
radius.control / radius.panel
elevation.control / elevation.dialog
fridge.frame / fridge.fill / fridge.divider / fridge.hinge
```

主题应用到 `<html data-theme="...">`。React 挂载前同步读取本地偏好并设置属性，避免首帧先显示水墨屏再跳到其他主题。

### 6.2 水墨屏

- 继续使用现有黑白与灰阶令牌、2–3px 轮廓和当前 SVG 图标。
- 既有冻结稿是本主题的视觉基线；升级后截图应无非预期变化。
- 不使用阴影、渐变或装饰纹理。

### 6.3 拟物

- 冰箱使用白色珐琅或中性金属材质、固定高光边、内凹隔板和小范围接触阴影。
- 控件允许轻微高光、按下位移和一层短阴影，但页面背景不得使用大面积照片、模糊或装饰性渐变。
- 文字与状态仍保持高对比；真实质感不能牺牲小尺寸图标辨识度。
- 避免把整套应用做成单一灰色金属色，状态色和内容色保持区分。

### 6.4 卡通

- 使用平面色块、清晰粗轮廓和轻量形变；不依赖渐变、玻璃或复杂阴影。
- 冰箱和分类图标共享同一轮廓语言与颜色饱和度。
- 避免整页被单一色相主导；主表面、强调色、状态色和中性色应有清楚分工。
- 字体尺寸和字距继续遵循项目规范，不使用随视口缩放的字号或负字距。

## 7. 冰箱 2.5D 主题渲染设计

### 7.1 分层职责

```text
Layout API 数据
  → fridgeLayoutCore：唯一几何计划
  → createFridgeIllustrationPlan：柜体、分区、格位和固定透视门平面
  → InkFridgeRenderer：现有语义 DOM/CSS
  → IllustrationFridgeRenderer：拟物/卡通 SVG 与透明图层拼接器
  → SemanticSlotOverlay：柜体矩形与门四边形可访问按钮
  → FridgePreviewFrame：setup/editor/location/home/thumbnail 尺寸约束
```

`fridgeLayoutCore` 不读取主题；主题切换不能改变业务布局。`createFridgeIllustrationPlan` 只把同一布局转换为主题无关的图层坐标和门四边形，不包含颜色、材质或图标。Kindle 继续消费现有 DOM 计划，不加载主题资产。

### 7.2 拼接几何

- 使用固定视角和固定门角，不提供自由相机或拖拽开门。整体按最长边等比缩放，保持 `FridgePreviewFrame` 的现有尺寸契约。
- 柜体、内胆和边框合并为一个逻辑皮肤；必要时拆为后景主体和前景 rim 两层，避免食材或隔板越过前框。
- 隔板只保留白色实体和玻璃两种共享组件；温区和主题决定皮肤，位置与长度由共享布局计划决定。首期省略抽屉。
- 每扇门拥有一个固定四边形局部平面。门体、门架、门上图标和交互按钮都映射到同一平面；左右门使用独立皮肤，拟物主题不得直接镜像带方向光影的资产。
- 七种模板可选择模板级柜体皮肤和门皮肤，但分区、格位与点击坐标仍由通用计划生成，页面不得各自维护模板几何。

建议场景计划结构：

```json
{
  "viewBox": [0, 0, 360, 480],
  "cabinet": { "rect": [16, 14, 238, 452], "skin": "shell" },
  "doors": [{ "id": "right-door", "plane": [[236,24],[344,39],[344,450],[236,468]] }],
  "slots": [{ "id": "slot-id", "parent": "cabinet", "rect": [40, 38, 190, 80] }]
}
```

### 7.3 主题皮肤与生成图片的职责

- 拟物主题使用 Soft-3D 奶油色皮肤、柔和环境阴影、磨砂内胆、玻璃隔板和中性金属合页；可由 SVG 渐变/滤镜或离线渲染的透明 WebP 表达。
- 卡通主题使用淡彩填充、统一暖灰描边和轻量阴影；与拟物主题共享图层结构和门平面，只替换皮肤。
- 水墨屏主题继续保留现有 DOM/CSS 渲染，确保冻结稿和 Kindle 兼容。
- 生成图用于确认整体风格和生产独立透明资产，不能作为携带业务格位的整张背景，也不能用于点击命中。
- 固定七模板可使用模板级皮肤以避免九切片拉伸光影；重复隔板和门架使用共享资产。

### 7.4 分类图标、状态与交互

- 分类图标以主题变体 SVG/透明 WebP 放入柜体或门的局部平面；门图标与门架一起使用固定透视变换。
- 选中、临期和过期状态使用独立几何或 DOM 覆盖层，不写入冰箱材质。
- 柜体格位使用矩形 DOM 按钮，门格位使用 `clip-path: polygon(...)` 四边形 DOM 按钮；按钮保留 `aria-label`、键盘焦点和可用热区。
- 贴图和 SVG 只负责视觉，不能注册独立业务点击；缩放后按钮必须与同一坐标计划同步。

### 7.5 性能与降级

- 主题皮肤进入带内容哈希的构建产物并按需加载；水墨屏和 Kindle 不承担拟物/卡通资产成本。
- SVG 和透明图层不运行连续动画；主题、布局或库存变化只触发普通 React 更新。
- 列表缩略图首期继续使用 DOM 语义降级，避免为每行加载高分辨率皮肤。
- 皮肤缺失、解码失败或浏览器不支持所需能力时回退当前水墨屏 DOM/CSS 冰箱，并保留全部格位交互。
- 体积预算重点约束主题皮肤和图标，单模板首屏只加载当前主题所需资产。

### 7.6 2.5D 验收

- 七种模板 × 拟物/卡通 × 默认/最大/不可用分格均需验证柜体、隔板、门平面、门架和遮挡。
- Playwright 在 320、390、430px 及宽矮/窄高容器检查 SVG/透明图层非空、framing 完整且无 UI 重叠。
- 自动化检查柜体按钮与矩形格位、门按钮与四边形格位一致，并验证皮肤缺失后的 DOM 回退。
- 真机覆盖至少一台 Android 和一台 iOS，记录首屏时间、资产缓存、缩放清晰度和后台恢复。

2026-08-18 决策记录：用户否决纯程序化 Three.js 视觉，单门验证改为共享 2.5D 拼接器。拟物主题从共享布局计划生成七种模板的柜体分区、动态隔板、一个或多个固定透视门平面、门架、合页和 DOM 格位覆盖层。标准、迷你和多层模板复用已验收完整 Soft-3D WebP 母版；宽体模板从同一母版拼接拉伸柜体片和右门片，左门及门架严格镜像右门。中隔板保留原右半框和左右上下圆角，只移除左圆角外侧高光，并在两内圆角之间以靠门位置的亮色凸角窄幅替换左侧边缘，中间亮色框体保持不动。不再用简化 SVG 重新绘制外壳。缩略图仍回退 DOM，卡通主题待单独生产皮肤。

## 8. 图标数据模型

### 8.1 推荐模型

`FoodCategory.icon_key` 保持不变。把 `IconAsset` 明确为逻辑图标集，并新增主题变体表：

```text
icon_assets
  key PK
  refrigerator_id NULL=内置，非空=自定义
  label
  fallback_theme CHECK(ink|skeuomorphic|cartoon)
  created_at

icon_asset_variants
  icon_key FK → icon_assets.key
  theme_key CHECK(ink|skeuomorphic|cartoon)
  media_type CHECK(image/svg+xml|image/png|image/webp)
  storage_path
  source
  created_at
  PK(icon_key, theme_key)
```

不建议给 `food_categories` 增加三个 `icon_key` 字段，也不建议把同一分类复制成三条记录；这两种方案都会把纯展示偏好泄漏进业务模型，并增加识别、食谱匹配和位置记忆的复杂度。

### 8.2 迁移

1. 新建 `icon_asset_variants`。
2. 将现有每条 `IconAsset` 的文件字段迁入 `theme_key=ink` 的变体。
3. `icon_assets.fallback_theme` 设为 `ink`。
4. 校验每个现有 `icon_key` 至少存在一个可读取变体后，再从逻辑表移除单文件字段。
5. 更新内置目录清单，为每个图标登记三个主题路径；启动同步必须拒绝缺少任一内置主题的目录。
6. 自定义旧图标迁移后只有水墨屏变体，其他主题自动借用该图标，不要求用户重新生成。

迁移必须验证升级前后的分类 ID、图标键、库存记录和自定义文件路径不变。

## 9. API 与前端类型

图标列表响应由单 URL 演进为逻辑图标及变体集合：

```json
{
  "key": "egg",
  "label": "鸡蛋",
  "fallback_theme": "ink",
  "variants": {
    "ink": { "asset_url": "...", "media_type": "image/svg+xml" },
    "skeuomorphic": { "asset_url": "...", "media_type": "image/webp" },
    "cartoon": { "asset_url": "...", "media_type": "image/webp" }
  }
}
```

- 前端只通过共享 `resolveIconVariant(icon, activeTheme)` 解析 URL，页面不得各自实现兜底顺序。
- 候选生成请求增加 `theme_key`；生成提示词由后端按受支持主题映射，客户端不能传任意风格提示词。
- 首次确认候选可创建逻辑图标和分类；已有自定义图标可新增或替换指定主题变体。
- 资产端点仍按当前冰箱鉴权；不能通过猜测 `icon_key/theme_key` 读取其他冰箱文件。
- 变体替换使用新修订 URL，避免旧 Cache Storage 条目继续显示。
- 删除冰箱、删除自定义小类或替换文件时，事务提交后清理对应全部变体文件；回滚时保留旧文件并删除新文件。

## 10. 偏好持久化与缓存

### 10.1 本机偏好

- 使用版本化键 `fridgeboard-theme-v1` 保存 `ink|skeuomorphic|cartoon`。
- 主题读取、校验、应用和订阅封装在独立模块；业务页面不直接访问 `localStorage`。
- 在 React `bootstrap` 前应用 `data-theme`、`color-scheme` 和 `<meta name="theme-color">`。
- 主题偏好不放入页面缓存，也不随切换账号清除；这是设备外观偏好，不是冰箱业务数据。

### 10.2 资产缓存

- 冰箱主题框体和内置 UI 资产进入带内容哈希的前端构建产物，由应用壳缓存管理。
- 分类图标的 Cache Storage 键必须包含完整变体 URL及修订值，避免三主题相互覆盖。
- 在线切换时立即加载目标变体，并在空闲时间预取当前冰箱可见图标的其他变体。
- 离线且目标变体从未缓存时，使用已缓存的 `fallback_theme`；不能显示破图或无限加载。
- 退出账号时继续清除受鉴权的运行时图标缓存，避免不同所有者共享自定义资产。

## 11. 规范冲突与处理建议

当前项目规范与主题需求存在明确冲突，进入实现前必须确认并修订规范：

1. `docs/ui-design-specification.md` §4 固定为黑白纸张令牌，并禁止阴影、渐变和装饰纹理；拟物与卡通主题需要受控的颜色、材质和立体层次。
2. 现有最终 UI 设计稿全部以水墨屏视觉冻结，尚无“应用偏好”“主题设置”、拟物或卡通主题基线。
3. 功能设计明确排除完全自由绘制冰箱，而“任意冰箱门数量”会扩展现有业务结构，不应隐藏在主题实现中。

建议将现行规范定义为 `ink` 主题规范，并新增“主题例外”章节：共享页面骨架、热区、响应式、状态语义和无障碍规则对三主题都强制；颜色、材质、边框、圆角及受控阴影由主题令牌决定。拟物主题只允许组件级短阴影和冰箱材质，不允许大面积背景特效、模糊或营销式装饰。

## 12. 资产生产与验收

### 12.1 冰箱资产

- 先用 `gpt-image-2` 为统一相机角度生成拟物概念图，再以同一构图派生卡通概念图，确认门姿态、材质和配色。
- 按结构族维护独立空母版，当前拟物主题至少包含单腔母版和双腔母版。单腔母版不得通过横向拉伸、门体镜像或中框切片拼成双腔；双腔母版必须保留左右门、左右内腔和中央分格各自的原生光影。
- 模板通过结构族选择母版：单腔模板使用单腔坐标，`side_by_side`、`french_door` 使用双腔坐标；隔板和门架共享材质规则但分别映射到具体腔体和门平面，业务格位不烘焙进贴图。
- 对拟物和卡通分别验证柜体深度、门轴、开门角度、内胆、隔板、合页、接触阴影及可选把手。
- 生成图片不得包含文字、品牌、格位数量、状态角标或食品图标；它们不进入生产运行时资源。

### 12.2 分类图标资产

- 46 个内置逻辑图标形成 138 个变体的完整矩阵。
- 用统一模板批量检查透明通道、画布尺寸、包围盒、中心偏移、边缘裁切、文件大小和媒体类型。
- 人工语义验收重点检查相似分类，如牛/猪/羊肉、饮料/酒/茶咖、个护/清洁用品。

### 12.3 建议体积预算

- 单个 256×256 透明栅格分类图标目标不超过 40KB，超出 80KB 必须优化或说明。
- 2.5D 拼接器保持轻量；单主题单模板皮肤目标不超过 500KB，首屏只加载当前主题和当前模板。
- 生产构建需要记录三主题引入后的压缩前后体积变化。

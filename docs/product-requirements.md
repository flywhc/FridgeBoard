# FridgeBoard 产品需求基线

状态：现行基线，PR-074、PR-076、PR-077、PR-078 待评审，其余需求已完成并验证
更新时间：2026-09-04
详细规则：[功能设计与可行性分析](functional-design-and-feasibility.md)
回归索引：[需求追踪与回归矩阵](requirements-traceability.md)

本文档是日常开发使用的精简需求清单。每条需求只保留可观察行为和不可破坏的约束；历史讨论、方案比较和逐会话实现记录不放在这里。

## 1. 产品边界

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-001 | 产品由手机 PWA/Capacitor 端和竖屏冰箱端组成；手机负责管理、录入、食谱和提醒，冰箱端负责低频展示和库存调整。 | 两端共享业务数据；冰箱端不依赖现代动画、悬停或复制文本。 |
| PR-002 | 手机可以管理多台冰箱；每台冰箱独立拥有布局、库存、食谱、设置和设备授权。 | 切换冰箱不串数据；搜索结果可定位并切换工作区。 |
| PR-003 | 服务为个人、免费、无广告的软件；冰箱端显示设备不承担所有者管理权限。 | 角色边界在页面入口和服务端接口双重生效。 |

## 2. 账号、配对与权限

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-010 | 所有者通过 flycn SSO 登录；PWA/显示设备通过短效二维码或兼容六位码取得独立、可撤销凭证。 | code/token 一次性、短效、消费后清理；未安装 App 时链接回到 PWA。 |
| PR-011 | 冰箱端绑定、手机配对、换绑和设备移除互相区分；每台冰箱最多一个活跃显示设备。 | 普通绑定不替换活跃设备；换绑成功才撤销旧设备；撤销后旧凭证立即失效。 |
| PR-012 | 所有者专属操作包括重命名、布局维护、设备管理、提醒设置、删除/恢复和管理入口；日常设备只能执行日常库存/食谱操作。 | 跨账号、错误角色和已撤销凭证均被拒绝。 |

## 3. 冰箱与布局

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-020 | 支持七种固定冰箱模板；创建后可直接使用，也可按模板约束配置温区、分格和门架。 | 手机预览、位置选择、首页和冰箱端使用同一布局几何。 |
| PR-021 | 分格可用/不可用、门区对应关系和自定义分层名称可持久化；名称变更同步到相关页面和设备端。 | 不允许自由绘制；非法位置和超出模板约束的布局被拒绝。 |
| PR-022 | 已有布局减少分格时，受影响库存自动归入同区域最后保留分格；布局、库存和失效位置清理原子完成并防止并发覆盖。 | 事务失败回滚；过期草稿要求刷新。 |
| PR-023 | 冰箱名称去首尾空白后为 1-120 字符；同一所有者的活跃冰箱名称唯一；删除为 30 天软删除，允许恢复但不恢复旧设备凭证。 | 可删除最后一台冰箱；到期可重复清理；恢复遇到重名自动编号。 |

## 4. 物品、分类与图标

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-030 | 物品必须有名称、小类和位置；数量默认 1；BBD 可选；生产日期、描述、价格和条码可选。 | 手工录入可独立完成；无 BBD 不产生临期/过期状态。 |
| PR-031 | 数量为 0 是可恢复的软删除状态，保留日期和批次信息但不进入首页统计、风险提醒或普通库存展示；批量真删除永久删除批次及消费审计引用。 | 清零/恢复不改日期；真删除不可恢复且仅所有者可用。 |
| PR-032 | 固定导航大类为八类：肉蛋水产、水果蔬菜、熟食主食、粮油酱料、酒水饮料、点心奶品、个护美妆、日化清洁；库存只持久化小类。 | 目录是分类唯一来源；历史移除节点只用于兼容展示，不进入选择和匹配。 |
| PR-033 | 添加物品展示最近 16 个不重复小类；支持全小类搜索、创建自定义小类、编辑/删除创建者自己的小类；自定义小类和图标按用户共享，同一用户的全部冰箱直接引用同一个小类 ID。自定义小类必须绑定有效逻辑图标。 | 最近分类顺序稳定；跨冰箱移动不复制分类；非创建者不能改删；无图标或无效图标的小类创建被后端拒绝；被库存、购物项或当前周及未来食谱引用的小类不能删除，删除失败列出具体橱柜位置、食谱菜名和食材；历史食谱不阻断删除；历史缺少逻辑图标的小类可在编辑时重新绑定图标。 |
| PR-034 | 同一逻辑图标支持水墨、拟物、卡通三主题；当前主题优先，缺失时按 fallback 和稳定顺序借用；内置图标只读，自定义图标 copy-on-write。 | 切换主题不改变分类、库存或食谱数据；任何主题不得显示破图。 |
| PR-035 | 图标来源包括内置图库、本地图片、Iconify、Thiings 和按主题的 AI 候选；本地图片等比缩放且不裁剪、不补边、不改主体占比，高置信度白色/奶白色边界背景在本机移除并保留原图回退。 | 已有透明度和半透明阴影保留；复杂或低置信度背景不得强制删除；SVG 经过白名单清洗；候选可选择、取消和清理；来源署名可追溯。 |

## 5. 录入、搜索与库存操作

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-040 | 支持手工录入、条码查询、包装照片识别和订单/长截图识别；AI 仅增量填写识别到的字段，用户已修改字段不能被静默覆盖。 | 相机拒绝或 AI 失败时仍可手工完成；冲突必须显式确认。 |
| PR-041 | AI/模型过程通过同域 SSE 提供阶段和增量反馈，不阻塞返回和手工编辑；识别图片任务结束、失败或超时后删除。 | 超时、取消、非 JSON 和上游错误均有可定位日志和可重试状态。 |
| PR-042 | 首页、分格和跨冰箱搜索复用物品列表；支持名称/分类/备注包含搜索、五种排序、本地记忆排序、多选分类、批量移动和批量删除。 | 数量为 0 排在正数后；价格排序无价格排最后；批量操作保持权限和数据完整性。 |

## 6. 食谱、补货与提醒

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-050 | 显示本周和下周，周一至周日固定顺序；支持多行导入、逐日编辑、添加/覆盖导入、做法/备注和最近食谱历史。 | 已完成食谱保留并显示完成态；删除完成食谱不恢复已扣库存。 |
| PR-051 | 食谱食材严格按小类和库存名称包含关系匹配；库存添加、拿走、迁移、扣减和撤销后动态重算缺货。 | 不以大类兜底，不误扣；缺货优先展示，数量 1 省略乘号。 |
| PR-052 | 完成食谱按最早 BBD 优先扣减库存；完成操作可整体撤销并恢复数量、日期风险和未完成状态。 | 扣减、审计和撤销原子一致；小数数量也可用。 |
| PR-053 | 支持动态补货清单、自定义购物清单和复制到剪贴板；提醒设置支持关闭、时间调整、Web Push 和应用内降级。 | 空清单复制不报错；提醒每日去重；无 BBD 不提醒；设备未同步可触发健康状态。 |
| PR-075 | 创建或编辑自定义小类后，扫描当前用户全部活跃自有冰箱的库存、食谱食材和自定义购物项，将匹配项归入该小类；购物清单展示对应小类图标。 | 保存/识别状态可见；识别结果可确认后返回；跨冰箱权限、历史食谱、零库存记录和未保存当前物品均正确处理。 |
| PR-077 | 每周食谱页面的中间内容区域支持水平平扫切换周次；无论向左还是向右平扫，都在“本周”和“下周”之间切换。 | 标题栏和底部导航不响应周次平扫；纵向滚动、按钮点击和现有本周/下周选择不受影响。 |

## 7. 冰箱端与主题

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-060 | 冰箱端固定水墨主题，首页按实际空间展示物品和风险，点击分区进入详情；食品图标不可单点操作。 | 低频同步、手动刷新、离线/失败状态和唤醒补同步可用。 |
| PR-061 | 手机 PWA 和 Capacitor 支持水墨、拟物、卡通主题；主题是本机偏好，默认拟物，不跨设备同步。 | 刷新/App 重启保留；未知值回退拟物；主题不改变业务语义和布局计划。 |
| PR-062 | 拟物/卡通冰箱皮肤由共享布局计划驱动；WebGL 或主题资产不可用时回退水墨 DOM/CSS，并保留格位交互。 | 七种模板及不同分格状态不出格、不遮挡、不丢点击热区。 |

## 8. PWA、移动端与运维

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| PR-070 | PWA 与 Capacitor 共用 React/Vite 页面和 FastAPI 业务 API；PWA 同源使用 Service Worker，原生 App 从包内加载静态壳并使用远程 HTTPS API。 | PWA 和 App 不互相污染缓存；网络异常时包内静态壳仍可打开。 |
| PR-071 | 原生 App 使用系统浏览器 SSO、Android Keystore/iOS Keychain、App Link/Universal Link、相机/扫码/分享/系统返回，并保留 Web fallback。 | 长期凭证不进 URL、localStorage、日志、剪贴板或普通 WebView Cookie；撤销/401 后停止有效业务访问并提示，但未经用户明确允许不得删除本地 token。 |
| PR-072 | 生产固定单 FastAPI/Uvicorn 进程、单容器副本和 SQLite WAL；调度器处理通知、清理、备份和幂等记录。 | 迁移前向兼容；日志可还原失败链路且脱敏；数据库和持久图标按规则备份，临时媒体不备份。 |
| PR-073 | 发布由脚本生成时间戳 release，统一前端/PWA/Android/iOS 版本信息；签名产物、健康检查和回滚信息可追溯。 | 不提交密钥、生产数据或调试包；生产 `/healthz` 与产物元数据一致。 |
| PR-074 | PWA 启动先从缓存显示应用 splash，再后台检查并同步当前 release；检查或升级失败不阻塞进入主界面，检测到新版本时 splash 显示“正在更新...”。 | 慢网、断网、Service Worker 注册失败和缓存清理异常均能进入主界面；新版本只在准备好当前应用壳后刷新，避免升级中黑屏。 |
| PR-076 | 业务页面缓存存在时立即展示且不显示自动刷新动画；仅无缓存无数据或用户下拉时显示动画。首页无缓存、release 变化及首页下拉完成后，串行静默刷新全部页面数据，当前进入的未完成页面优先；刷新不得改变页面栈。 | 普通切页不自动请求或写缓存；用户写操作按影响范围同步缓存且不被更早读取覆盖。账号切换取消旧任务并禁止跨账号回写。删除不存在保持幂等、无权限仍拒绝；保存覆盖并发服务端修改，目标不存在时提示并放弃。 |
| PR-078 | 原生 App 登录后保持会话；除用户主动退出或在故障说明中明确选择“重新登录”外，任何自动路径都不得清除本地 token 或跳到重新登录页。短暂断网、超时、服务不可用、安全存储异常和服务端拒绝只记录状态并保留当前缓存页面。 | 故障页面区分原因并允许提交脱敏错误信息、选择“稍后再试”或“重新登录”；诊断包含稳定编号、阶段、原因、时间、release 和安全环境信息，不包含 token、Cookie、用户业务数据或原始输入；Android 加密会话不进入系统备份。 |

## 9. 明确不属于当前需求

- 不支持多所有者协作、共享管理员或离线库存/食谱写入。
- 不支持任意自由绘制冰箱结构，不以整张概念图承担业务点击。
- 不把食品照片长期保存，不把用户原图改造成裁剪或改变主体占比的图标。
- 不引入多容器、多副本、PostgreSQL、Redis、消息队列或第三方监控平台来解决首版规模问题。
- App Store/Google Play/TestFlight 的商店运营不是当前发布基线；侧载 APK 和现有 iOS 签名流程以移动端部署设计为准。

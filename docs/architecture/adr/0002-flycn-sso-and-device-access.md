# ADR-0002：复用 flycn 用户身份与设备访问模型

状态：已接受  
日期：2026-07-19

## 决策

`app.flycn.fyi` 是 FridgeBoard 的唯一账号和密码身份源。FridgeBoard 通过 SSO 回跳、60 秒单次授权码和私网兑换接口建立自己的持久管理会话；不读取 flycn SQLite，不共享 Cookie、签名密钥或密码哈希。

任意 flycn 活跃用户均可成为冰箱所有者。每台冰箱只有一个所有者。未登录手机通过冰箱端显示设备的二维码取得独立、可撤销设备凭证，并可执行日常库存和食谱操作；所有者专属操作仅限已登录管理会话。

## 账号恢复、冰箱端绑定与手机配对

1. 同一 flycn 账号在不同手机登录后，直接恢复该账号拥有的全部活跃冰箱和管理权限；这不依赖设备二维码。
2. 未配置冰箱端显示 `bind_display_device` 短效二维码。手机领取前必须完成所有者登录，可选择已有冰箱，或创建 `needs_layout` 的待完成冰箱记录。
3. 已配置冰箱端显示 `grant_pwa_access` 短效二维码。手机扫码只为当前 PWA 实例签发日常访问凭证，不改变冰箱所有者。
4. 冰箱端普通绑定不得替换已有活跃冰箱端；所有者明确发起 `replace_display_device` 后，新设备成功取得凭证时才在同一事务中撤销旧设备。
5. 6 位数字 Passcode 保留为二维码不可用或旧设备的兼容路径，并同样区分普通绑定与换绑用途。
6. 每台冰箱最多一个活跃冰箱端显示设备；每个 PWA 实例与冰箱的访问凭证独立、可撤销，重复消费同一二维码保持幂等。

## 后果

- Passcode 与二维码均只在服务端保存哈希和值的状态，不作为长期访问凭证。
- 冰箱记录以 `needs_layout | ready` 显式记录设置进度，不再通过默认模板、库存或是否存在格位推测。
- 账号拥有权、PWA 实例日常访问权和冰箱端显示设备绑定是三个独立关系；接口必须返回当前访问角色和冰箱端绑定状态。
- 管理会话为长期持久会话；flycn 后续的改密码、改角色或禁用状态仅在下次 FridgeBoard 登录时生效。这是为当前低安全、家庭使用场景选择的简化取舍。
- 清除浏览器数据、撤销设备或删除冰箱后，相关设备须重新配对。

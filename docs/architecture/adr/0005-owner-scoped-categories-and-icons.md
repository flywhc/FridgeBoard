# ADR-0005：用户级共享分类与图标

状态：已接受

## 背景

旧模型把自定义小类和图标归属到单台冰箱。跨冰箱识别或移动库存时必须复制分类，导致同一用户出现多个同名小类 ID、共享图标却保留源冰箱归属，以及库存、食谱和购物项指向不同副本。分类名称、所属大类和图标元数据因此可能失去一致性。

## 决策

- 内置分类和图标的 `owner_user_id` 为 `NULL`；自定义分类和图标以 `owner_user_id` 归属用户。
- 同一用户的所有冰箱、库存批次、食谱食材和购物项直接引用同一个自定义小类 ID，不创建冰箱副本。
- 用户级自定义大类按 `(owner_user_id, name)` 唯一；小类按 `(owner_user_id, parent_id, name)` 唯一。
- API 仍以冰箱 ID 提供操作上下文和鉴权，但分类与图标访问通过该冰箱的所有者解析；不同用户之间严格隔离。
- 图标标签属于资产元数据，不作为分类身份；编辑分类图标时同步资产标签，业务关联始终使用分类 ID。
- 删除单台冰箱保留该用户共享分类和图标；清理用户最后一台冰箱时才清理无其他使用方的用户级资产。

## 迁移

迁移按用户、规范父级和名称合并历史分类副本，优先保留修订号高且业务引用多的记录，并重写库存、食谱、购物、最近使用、名称映射和图标草稿外键。迁移后执行 SQLite 完整性、外键和重复分类检查。

## 结果

跨冰箱移动和识别不再复制分类。分类名称、所属大类、图标和各业务页面的关联从同一分类记录解析；名称识别缓存仍可按冰箱保留上下文，但其结果指向用户级分类 ID。

# 手机首次使用、冰箱端绑定与换绑流程设计

状态：设计完成，待产品评审与实施  
版本：0.1  
日期：2026-08-07  
关联范围：P3 配对与设备权限、P4 创建冰箱、P7/P7.1 冰箱列表与设置、P12 启动恢复

## 1. 背景与问题

冰箱端首次打开会显示配对二维码，但当前手机端首页没有稳定、可发现的扫码入口。用户从
系统相机扫描二维码后进入短效 `/pair` 地址和安装引导；虽然 PWA Manifest 已将
`start_url` 固定为 `/`，安装后的长期入口是手机端首页，但现有页面没有解释这一点，也没有
把用户可靠地引回“打开 PWA—再次扫码—绑定或创建冰箱”的完整流程。

同时，现有实现把以下概念混在了一次“配对”操作中：

- 登录账号拥有的冰箱记录；
- 冰箱布局是否已经完成；
- 当前 PWA 安装实例是否获准访问某台冰箱；
- Kindle 等冰箱端显示设备是否绑定到该冰箱；
- 短效二维码是否仍然有效。

本设计拆分这些状态，并统一首次安装、账号恢复、添加已有冰箱、创建布局、绑定冰箱端和
更换冰箱端设备的入口与提示。

## 2. 已确认产品决策

1. 安装后的 PWA 长期启动地址固定为 `/`，即 `https://fridge.flycn.fyi/`。配对 URL
   只承载短效、单次使用的会话，不作为快捷方式或长期导航地址。
2. 同一 flycn 账号在不同手机登录后，恢复该账号拥有的全部活跃冰箱及其管理权限；这是
   账号恢复，不需要重新扫码。
3. 扫描一台已配置冰箱的“添加手机”二维码，只为当前 PWA 安装实例增加访问凭证，不改变
   冰箱所有者。
4. 每台冰箱仍只有一个所有者。其他账号或未登录 PWA 通过扫码获得日常访问权，不获得
   重命名、布局维护、设备管理、删除或恢复权限。
5. 冰箱记录、布局完成状态和冰箱端绑定状态相互独立。允许存在“冰箱记录已创建，但布局
   尚未完成”以及“布局已完成，但尚未绑定冰箱端设备”的状态。
6. 未配置冰箱端不能匿名创建无所有者冰箱。扫描未配置设备后，若需要创建新冰箱，必须先
   登录，由该账号成为唯一所有者。
7. 一台冰箱同一时间只允许一个活跃冰箱端显示设备。换绑成功后撤销旧设备；换绑失败时旧
   设备继续有效。
8. 六位兼容绑定码保留为不支持二维码扫描或旧设备的兼容路径，不再作为手机端默认流程。

## 3. 身份、记录与设备模型

### 3.1 所有者账号

- 账号登录后从服务端恢复其拥有的全部冰箱。
- 所有者可以创建、重命名、编辑布局、绑定或换绑冰箱端、管理访问设备、删除和恢复冰箱。
- 在新手机登录同一账号，不应要求用户重新扫描自己拥有的冰箱才能看到列表。

### 3.2 PWA 安装实例

- 每个浏览器或 PWA 安装实例仍是独立设备。
- 扫描“添加手机”二维码后，为“当前 PWA 实例 × 目标冰箱”签发独立、可撤销凭证。
- 清除网站数据、换浏览器或卸载 PWA 会丢失实例凭证，但不会影响登录账号拥有的冰箱记录。
- 同一冰箱已在当前实例列表中时，再次扫码应幂等处理：提示“这台冰箱已经添加”，直接打开，
  不重复显示列表条目。

### 3.3 冰箱端显示设备

- 未绑定设备展示“绑定冰箱端”二维码。
- 已绑定设备可展示“添加手机”二维码，为其他 PWA 实例授予访问权。
- 进入换绑流程的新设备必须展示设备绑定二维码，不能复用“添加手机”二维码。
- 一个已绑定到其他冰箱的设备不能被静默迁移；应先解除原绑定或在设备端执行明确重置。

## 4. 冰箱状态模型

| 冰箱记录 | 布局 | 冰箱端 | 手机端状态与主操作 |
| --- | --- | --- | --- |
| 不存在 | 无 | 未绑定设备显示二维码 | 扫码后登录并创建冰箱 |
| 已存在 | 未完成 | 已绑定 | “待完成设置”；继续创建布局 |
| 已存在 | 未完成 | 未绑定 | “待完成设置”；继续布局，之后绑定设备 |
| 已存在 | 已完成 | 未绑定 | 正常显示首页；持续提示“绑定冰箱端设备” |
| 已存在 | 已完成 | 已绑定 | 正常使用 |
| 已存在 | 已完成 | 换绑中 | 旧设备继续有效；新设备成功后原子切换 |

冰箱需要持久化明确的设置状态，例如 `setup_status = needs_layout | ready`。不得通过模板名、
是否存在默认布局或库存数量推测是否完成设置。

## 5. 手机端信息架构

### 5.1 未登录或空首页

标题：`开始使用家常食橱`

说明：

> 扫描冰箱屏幕上的二维码，连接已有冰箱；或登录后查看和创建你的冰箱。

操作：

- 主操作：`扫描冰箱二维码`
- 次操作：`登录或注册`

登录完成后：

- 有布局完整的冰箱：恢复列表，优先打开上次使用且仍可访问的冰箱；
- 只有待完成冰箱：进入“我的冰箱”，突出显示“继续设置”；
- 没有冰箱：显示明确的`创建新冰箱`操作，不未经选择直接进入创建流程。

### 5.2 扫码入口

同一个扫描器由三个入口复用：

1. 空首页的`扫描冰箱二维码`；
2. “我的冰箱”顶部的添加入口，用于添加已有冰箱或发现未配置设备；
3. 某台冰箱设置中的`绑定冰箱端设备`或`更换冰箱端设备`。

从冰箱设置进入时已携带目标冰箱 ID，扫码后直接绑定该冰箱，不再要求用户选择目标。只有
从空首页或“我的冰箱”通用入口进入时，才根据二维码类型及账号状态让用户选择已有冰箱或
创建新冰箱。

扫描器必须识别：

- 未配置/换绑设备的 `bootstrap` 二维码；
- 已配置冰箱的“添加手机”二维码；
- 非本产品二维码；
- 已过期、已使用、已由其他手机领取的二维码。

### 5.3 未完成冰箱

“我的冰箱”条目显示：

- 状态徽标：`待完成设置`
- 已绑定设备：`已连接冰箱端 · 尚未创建布局`
- 未绑定设备：`尚未连接冰箱端 · 尚未创建布局`
- 主操作：`继续设置`
- 次级管理入口：允许删除未完成冰箱。

创建流程应保存服务端草稿。用户中途退出、关闭 PWA 或更换手机后，登录同一账号仍可继续。

### 5.4 布局完成后的绑定引导

用户在手机端主动创建了冰箱布局、但尚未绑定冰箱端时，布局保存成功页显示：

> 冰箱布局已创建  
> 接下来可以绑定冰箱端设备，让冰箱屏幕显示这个布局。

- 主操作：`扫码绑定冰箱端`
- 次操作：`稍后绑定`

如果用户此前已扫描未配置冰箱端，并且该会话仍有效，布局保存后自动完成绑定，不要求第三次
扫码。

选择“稍后绑定”后：

- 当前冰箱首页显示非阻塞提示：`尚未绑定冰箱端设备`和`扫码绑定`；
- “我的冰箱”条目显示：`布局已创建 · 冰箱端未绑定`；
- 冰箱设置始终提供正式绑定入口。

### 5.5 冰箱设置

设备区将“手机访问”和“冰箱端设备”分组展示。

未绑定冰箱端：

> 冰箱端设备  
> 尚未绑定  
> 扫描冰箱屏幕上的绑定二维码，让该设备显示这台冰箱。

按钮：`绑定冰箱端设备`

已绑定冰箱端：

> 当前绑定：厨房 Kindle  
> 最近同步于 10:32

按钮：`更换冰箱端设备`

换绑确认：

> 新设备绑定成功后，当前冰箱端将停止访问。扫描失败或取消不会影响当前设备。

兼容入口：`使用六位绑定码`作为次级操作，仅在二维码不可用时使用。

## 6. 端到端流程

### 6.1 第一次使用：从未配置冰箱端开始

```text
冰箱端显示二维码
→ 用户用系统相机扫码，或访问 fridge.flycn.fyi
→ 浏览器展示分平台安装引导
→ 从主屏幕打开 PWA 首页
→ 点击“扫描冰箱二维码”，扫描冰箱端当前二维码
→ 未登录时登录，并在登录回跳后恢复本次绑定意图
→ 创建“待完成设置”的冰箱记录并绑定冰箱端
→ 创建布局
→ 冰箱状态变为 ready，冰箱端自动进入首页
```

二维码若在安装或登录期间过期，不尝试复用旧 token；手机提示用户回到冰箱端扫描当前二维码。

### 6.2 手机已有布局，绑定新的冰箱端

```text
打开目标冰箱
→ 冰箱首页提示或冰箱设置
→ “绑定冰箱端设备”
→ 扫描未配置设备二维码
→ 确认目标冰箱名称
→ 绑定成功
```

### 6.3 添加一台已配置冰箱到当前手机

```text
已配置冰箱端打开“添加手机”二维码
→ PWA 通用扫描器扫码
→ 为当前 PWA 实例签发访问凭证
→ 已有布局直接加入列表并打开首页
```

如果当前登录账号不是所有者，只获得日常访问权；设置页不得显示所有者专属操作。

### 6.4 同一账号在新手机登录

```text
打开 PWA 首页
→ 登录同一 flycn 账号
→ 恢复该账号拥有的所有冰箱
→ 打开上次使用且仍存在的冰箱，或进入冰箱列表
```

该流程不要求重新扫描。扫码产生的其他所有者冰箱访问权仍属于具体 PWA 实例，不因账号登录
自动同步到其他设备。

### 6.5 更换冰箱端设备

```text
冰箱设置
→ “更换冰箱端设备”
→ 阅读旧设备影响
→ 扫描新设备的绑定二维码
→ 服务端验证新设备可绑定
→ 同一事务中绑定新设备并撤销旧设备
→ 手机与新设备显示成功；旧设备下次请求显示访问已移除
```

## 7. 页面提示语

### 7.1 冰箱端首次/未配置页

标题：`绑定手机端`

二维码下方：

> 首次使用：用手机相机扫描，或打开 fridge.flycn.fyi 安装“家常食橱”。  
> 已安装：打开“家常食橱”，进入这台冰箱的“冰箱设置”，点击“绑定冰箱端设备”后扫描。

状态：`二维码将在 09:52 后更新`

由于未配置设备还没有冰箱名称，“进入这台冰箱的冰箱设置”只适用于用户已经在手机创建好
目标冰箱布局的场景；手机通用扫码入口仍必须支持创建新冰箱。

### 7.2 浏览器安装引导

标题：`先安装家常食橱`

说明：

> 安装后的应用会从首页打开。本次二维码仅用于连接冰箱，并会在短时间后失效。  
> 安装完成后，从主屏幕打开“家常食橱”，点击“扫描冰箱二维码”，再扫描冰箱屏幕上的当前二维码。

页面在展示安装说明后应移除地址栏和历史记录中的短效查询参数，但不能提前消费配对会话。

### 7.3 配对结果

已有布局：

> 已添加“厨房冰箱”  
> 正在打开冰箱首页……

尚无布局：

> 冰箱端设备已连接  
> 接下来为“厨房冰箱”创建布局。

主操作：`创建冰箱布局`

重复扫码：

> 这台冰箱已经添加到当前手机。正在打开冰箱首页……

二维码失效：

> 二维码已失效或已被使用。请回到冰箱屏幕，扫描当前二维码。

## 8. 数据与接口影响

实施前需要完成以下领域设计：

1. 为冰箱增加显式设置状态及草稿恢复字段；现有创建接口不能再以默认 `mini` 布局代替
   “尚未完成布局”。
2. 分离“创建待完成冰箱”“保存布局并完成设置”和“绑定冰箱端”事务。
3. 配对会话增加明确用途：`grant_pwa_access`、`bind_display_device`、`replace_display_device`。
4. 绑定会话保存可选目标冰箱和登录回跳意图，但不把短效 token 写入 PWA 长期启动地址。
5. 冰箱列表需要合并账号拥有的冰箱与当前实例获准访问的冰箱，同时返回权限角色、布局状态
   和冰箱端绑定状态。
6. 增加幂等约束，避免同一 PWA 实例重复扫码后出现重复列表项或无意义的重复凭证。
7. 为每台冰箱约束至多一个活跃冰箱端设备；换绑必须事务化。
8. 设备绑定、换绑和撤销写入审计信息，至少包含操作者、目标冰箱、旧/新设备和时间。

## 9. 实施计划

### 阶段 1：领域模型与 API 契约

- 冻结状态机、权限矩阵、二维码用途和错误码；
- 设计数据库迁移与历史冰箱状态回填；
- 新增失败用例覆盖未完成布局、重复扫码、跨账号扫码、换绑回滚和 token 过期；
- 更新 ADR-0002，明确账号恢复与设备实例授权的边界。

### 阶段 2：后端状态与配对服务

- 实现待完成冰箱和布局完成状态；
- 拆分手机访问授权与冰箱端绑定会话；
- 实现单活跃冰箱端及原子换绑；
- 提供统一冰箱列表所需的角色与状态字段；
- 保留六位绑定码兼容接口。

### 阶段 3：手机端首页、扫码与创建流程

- 新增空首页双入口；
- 统一扫描器支持两类二维码及全部错误状态；
- 登录回跳恢复绑定意图；
- 未完成冰箱列表和继续设置；
- 布局完成后的即时绑定引导及持续未绑定提示；
- 配对成功后按布局状态分流。

### 阶段 4：冰箱设置与换绑

- 设备区拆分手机访问和冰箱端；
- 实现绑定、换绑、取消、失败回滚和兼容码入口；
- 按所有者/访问者权限隐藏或禁用管理操作；
- 更新冰箱列表状态和首页提示。

### 阶段 5：冰箱端页面与文案

- 未配置页显示首次使用/已安装双路径提示；
- 已配置页明确“添加手机”用途；
- 增加等待布局、绑定成功、二维码自动刷新和访问被撤销状态；
- 按 DP75SDI 的 ES5 与真实设备约束实现和验收。

### 阶段 6：迁移、回归与真实设备验收

- 回填现有冰箱为 `ready`，按活跃 Kindle 凭证推导绑定状态；存在多 Kindle 时先报告并制定
  数据清理策略，不静默删除；
- 运行后端 Ruff、全量测试、锁文件检查、前端 lint/test/build；
- 在 iPhone Safari/主屏幕 PWA、Android Chrome/安装 PWA 和 DP75SDI Kindle 上覆盖全部主流程；
- 验证安装入口始终从 `/` 启动，过期 token 不残留为应用入口；
- 验证同账号跨手机恢复、不同账号扫码权限、解绑/换绑和离线设备撤销。

本设计更新。实施前至少补齐或修订：

- 通用冰箱二维码扫描页；
- 未完成冰箱列表条目；
- 布局完成后的绑定引导；
- 冰箱设置中的绑定与换绑状态；
- 换绑确认与成功/失败；

DP75SDI 约束；设计资产确认并登记到 `docs/final-ui-designs.md` 后才能进入 UI 实施。
